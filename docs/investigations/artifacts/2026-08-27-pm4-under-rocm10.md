# What lowering to PM4 adds, measured against ROCm 10.0

**Status: internal. NOT posted upstream.**

Harness: `cargo run --release --example dispatch_floor -p redline-dispatch` from
the 2026-07-14 certification checkout. Runtime selection verified with
`LD_DEBUG=libs`, which shows the loaded ROCr per arm
(`/opt/rocm/core-7.14/lib/libhsa-runtime64.so` vs `core-10.0/...`) — necessary
because redline dlopens `libhsa-runtime64.so.1` by soname, so with no
`LD_LIBRARY_PATH` the loader silently picks whatever `/opt/rocm/core` resolves
to, and that symlink now points at 10.0.

## 1. PM4 is unaffected by ROCm 10.0

gfx1201, N=512 dispatches/replay, M=100 timed replays, 20 warmup. µs per
dispatch:

| path | ROCr 7.14 | ROCr 10.0 |
| --- | ---: | ---: |
| AQL `SystemEveryDispatch` (models HIP's per-dispatch fence) | 2.3287 | 2.3407 |
| AQL `AgentEveryInternalDispatch` | 2.1065 | 2.1115 |
| AQL `BoundarySerialized` (dependency-preserving) | 1.3041 | 1.3063 |
| AQL `BoundaryIndependent` | 1.0759 | 1.0782 |
| **PM4 retained IB, conservative** | **0.1471** | **0.1493** |
| **PM4 retained IB, aggressive** | **0.0713** | **0.0713** |

Every row is unchanged; the aggressive PM4 arm is identical to four digits. The
ROCm 10.0 graph-scheduling change does not touch this path, which is expected —
redline calls `hsa_queue_create` and owns its queue rather than going through
CLR's graph or stream machinery.

## 2. The full ladder on one architecture and one runtime

gfx1201, ROCm 10.0, µs per dispatch. HIP rows from
`bench/dispatch/aql_dispatch_floor.cpp` and
`bench/dispatch/graph_dependency_fencing.cpp`; redline rows from the table above.

| path | us/disp | vs hipGraph |
| --- | ---: | ---: |
| HIP, launch + sync per dispatch | 18.52 | 0.12x |
| HIP, N launches one stream | 2.55 | 0.84x |
| HIP hipGraph replay (chain) | 2.147 | 1.00x |
| HIP hipGraph, independent or fanout (10.0 converges them) | ~2.19 | 0.98x |
| AQL `AgentEveryInternalDispatch` | 2.112 | 1.02x |
| AQL `BoundarySerialized` | 1.306 | **1.64x** |
| AQL `BoundaryIndependent` | 1.078 | 1.99x |
| **PM4 retained IB, conservative** | **0.149** | **14.4x** |
| **PM4 retained IB, aggressive** | **0.071** | **30.1x** |

Measurement bases differ and the difference does not favour PM4: the AQL rows are
GPU-timestamped dispatch spans, the PM4 rows are end-to-end host latency per
replay, so the PM4 rows include host submission cost.

Note the independent cross-check: the standalone HIP probe measures hipGraph at
2.147 and redline's separately-modelled agent-scope fence policy lands at 2.112,
1.7% apart, from two harnesses sharing no code. hipGraph uses agent-scope
fencing, so the ladder is anchored to the real API rather than floating.

## 3. The augmentation: 10.0 removed HIP's only competitive concurrent path

This is what the ROCm 10.0 work changes about the comparison, and it is
architecture-dependent.

On **gfx1100**, redline's best AQL policy is `BoundarySerialized` at 2.0594
us/disp. HIP's concurrent-graph path under 7.14 reached **1.031** — i.e. under
7.14, HIP's independent-node graph *beat* redline's best AQL policy on that part.
Under 10.0 the same shape is **2.784**, which is now worse than redline's 2.0594.

| gfx1100 | 7.14 | 10.0 |
| --- | ---: | ---: |
| HIP hipGraph, independent nodes | **1.031** | **2.784** |
| redline AQL `BoundarySerialized` | 2.0594 | 2.0594 |
| verdict on that pairing | HIP ahead 2.0x | redline ahead 1.35x |

So ROCm 10.0 did not narrow the gap redline exists to exploit; on RDNA2/3/3.5 it
widened it, by removing the one HIP path that was competitive. On RDNA4 the
comparison is unchanged, because gfx1201's concurrent-graph path was never
competitive there (6.458 under 7.14).

## 4. Coverage gap that blocks capitalising on this

The deployed certification build refuses non-gfx12 parts for the PM4 path:

```
Error: ArchitectureMismatch { required: "gfx12", actual: "gfx1100" }
```

Current master is broader — `Pm4Family::from_name`
(`crates/redline-dispatch/src/aql/graph_pm4.rs:151`) resolves `gfx10`, `gfx11`
and `gfx120`, with `Gfx11Pm4CommandBuffer` aliased to the gfx10 register map. So
the PM4 number on gfx1100 and gfx1151 is currently **unmeasured, not
unavailable**: master supports those families and the July snapshot on the test
hosts does not.

That matters because §3 says the largest new opportunity is precisely on
gfx1100/gfx1151, where 10.0 regressed HIP's concurrent path — and those are the
two architectures where the PM4 comparison cannot be run with what is deployed.

## What is NOT established

- No PM4 measurement on gfx1100, gfx1151 or gfx1030. The 14.4x and 30.1x figures
  are gfx1201 only.
- The kernel is a no-op. These are submission-overhead ratios; real kernels
  dilute them toward 1x as compute grows.
- Nothing here measures multi-queue PM4 replay, which master supports and which
  is the natural follow-up given that 10.0 caps hipGraph at one queue while
  explicit streams still fan out to four.
